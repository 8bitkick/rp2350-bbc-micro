# Revision 11: optional web diagnostics

CMake option WEBDIAG defaults OFF. The supplied r11 combined UF2 uses OFF for Master, Model B and C64.

OFF hides the browser trace panel, detailed C64 recovery/failure banner and Test speaker button. It disables browser trace collection/sessionStorage writes. Normal keyboard, sound/volume, Turbo and ambient LED controls remain. The existing firmware fault capture, watchdog fallback and JSON diagnostic fields remain available; this is a web-interface option, not removal of recovery protection or backend instrumentation.

ON restores those diagnostic controls. CMake syntax is -DWEBDIAG=ON (not -WEBDIAG).

For a fresh combined build from the source root:

    OS_CMAKE_ARGS='-DSOUND=ON -DAMBIENT=ON -DWEBDIAG=ON' sh scripts/build-dual-boot.sh build-dual-boot

For existing build directories, reconfigure all three machine caches before rebuilding (the build script otherwise reuses their settings):

    cmake -S . -B build-dual-boot/master -DWEBDIAG=ON
    cmake -S . -B build-dual-boot/beeb -DWEBDIAG=ON
    cmake -S . -B build-dual-boot/c64 -DWEBDIAG=ON
    sh scripts/build-dual-boot.sh build-dual-boot

Use OFF instead to return to the regular interface. Hard-refresh the browser after flashing. Existing browser session trace data is not deleted, but OFF does not read it or append new entries.

Validation: generated compressed pages were decoded and browser-tested in both ON and OFF modes. Diagnostic visibility, ordinary controls and absence of OFF-mode trace storage were checked. All firmware built with OFF; combined image contents, bounds and ZIP integrity verified. This does not change r10 autoload/Turbo/ambient behaviour or resolve the outstanding quiet audio issue.
